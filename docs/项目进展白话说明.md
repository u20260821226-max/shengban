# 人工校正以后，我们做了什么

## 先记住主线

先用人工校正的曲目证明“声伴能帮助练习”，再让程序自己处理用户上传的谱图，最后把处理程序放到云服务器，让别人离开你的电脑也能使用。

## 1. 人工校正：准备可靠的示范

你用 Audiveris 把图片识别成乐谱，再在 MuseScore 修改错音、节奏、小节和声部。这样准备了《爱永在》《小幸运》《有一种悲伤》。这些曲目适合演示练习功能，但不能证明自动识谱已经准确。

MusicXML 可以理解为“电脑能读懂的乐谱”；MIDI 可以理解为“哪些音在什么时候弹、弹多久的指令”；MP3 是已经录好的声音。初期示范曲目使用导出的 MIDI 数据播放，后来自动识谱直接从 MusicXML 读取音符，不要求每次经过 MIDI 文件。

## 2. 播放器：把能响变成能练习

我们让网页用钢琴音色播放音符，接入速度、移调、跳转小节、循环和倒数。三行谱可以只听下面两行伴奏，也可以加上最上面的旋律提示。MP3 作为备用录音，保持原调原速。

意义：验证这个练习方式有没有用。你不必先解决所有识谱问题，才能让别人体验产品。

## 3. 识谱探索：发现原始方案的局限

我们对比过免费识谱、付费识谱和人工校正的路线，考虑费用、操作难度和比赛时间，先选择免费 Audiveris。没有购买付费软件做统一准确率测试，因此不能说已经证明谁更准确。

你回顾《爱永在》校正最少，《小幸运》其次，《有一种悲伤》最多；另外几首严重错乱。这是重要的使用经验，但没有逐音统计，不能把它写成准确率数据。

这里的关键发现是：识谱软件装好了，不代表任意谱图都能变成可靠伴奏。要求每位用户像你一样校谱，也偏离了“上传就能听”的初衷。

## 4. 自动流程：把重复操作写成程序

现在的流程是：上传谱图 → 程序调整图片 → Audiveris 识谱 → 检查声部与节拍 → 提取音符 → 网页钢琴播放。

我们对《光》《花非花》试过灰度处理与不同放大尺度。看起来清晰的图片，也可能不符合识谱工具需要的谱线间距。调整输入后，有些结果明显改善。不是简单地“图片像素越多越准确”，也不是所有失败都能靠放大解决。

这些步骤由代码自动执行，不需要用户每上传一张谱，就把图片交给聊天 AI 手工处理。识别模型来自 Audiveris，我们主要实现了输入处理、工具接入、结果检查与练习体验。

## 5. 结果检查：不能把明显错乱当成成功

我们重点检查小节是否超拍、缺拍，以及钢琴两只手是否完整。过程里也修正过自己的检查错误：多声部不能简单相加拍数，也不能要求每个局部声部都填满小节；同时，右手完整不能掩盖左手缺拍。

现在遇到部分结构疑点会自动换尺度重试一次；仍有严重问题则说明失败。检查通过只代表没有发现这些结构异常，不保证每个音都正确。少量错音和漏连线仍可能存在。

意义：先诚实地限定能处理的范围，而不是把任何结果都显示为“生成成功”。

## 6. 公网部署：让别人也能使用

GitHub 保存代码，Cloudflare 曾负责托管最初的网页。它们和识谱服务器是不同东西：能打开曲库，不等于能在网上运行 Java 识谱程序。

我们比较过托管方式和免费资源限制，最终使用阿里云试用服务器。它就是放在云机房里的另一台电脑。安装识谱程序、后台接口和网站后，用户的图片由它处理，你的 Mac 不必一直开机。

过程里遇到过登录权限、代理网络、安装依赖和网站端口未放行的问题。最终完成服务器连接、加密访问和公网测试；还加了上传限制、任务归属检查、处理超时和临时文件清理，避免无限占用服务器。

## 7. 多页和两种谱型：更接近真实使用

新增方向是同一首歌最多六页，先排好页序，再合成一份连续伴奏。两行钢琴谱完整播放双手；三行声乐谱保留纯伴奏和旋律提示。两种谱型不能在同一任务中混用。

曲库、上传、识别进度和试听现在放进同一个网站内部切换。具体完成情况以公网部署说明里的测试记录为准；程序生成的简单测试谱不能代替真实六页歌曲的准确性验收。

## 最终是否如意

阶段性达到了目标：预置曲目可以练习，符合范围的谱图可以自动生成试听，云端服务已能独立运行。

仍未达到“任意乐谱都能准确生成”的理想状态。复杂节奏、反复、多声部识别和输入质量仍有限制；更多真实谱图的试听验收还需要继续做。最合适的定位是“有限范围内可体验的自动伴奏演示”，而不是成熟、通用的商业识谱产品。

报告可以如实区分：你提出需求、准备并校正曲目、判断音乐效果、参与方案取舍和验收；AI 辅助实现代码、排查问题和部署。技术方案比较也不等于已经做过同学访谈，两类调研应分别记录。
