# 自动识谱本机测试

当前补充（2026-10-26）：已支持两行/三行及1至6页图片或单份最多6页PDF。启动前应在同一个Python环境安装 `backend/recognition-requirements.txt`（Pillow、pypdfium2）；以下早期单页记录保留为历史。当前统一公网入口和PDF验收见《公网识谱部署》《PDF接入与验证》。最新完整测试集为55项。

2026-10-24：用户试听《光》后认为整体效果可用，仍有连线遗漏。此结果只证明单个样本的可行性，不代表所有支持范围内的谱子均准确。

## 启动与使用

1. 本机已安装 Audiveris（含 Java）及 Pillow。双击根目录“启动自动识谱测试.command”，保持终端打开，访问 http://localhost:4175/ 。
2. 选择一张 JPG/PNG 单页三行声乐谱，点击“识别并生成试听”。不需要人工改谱或导出 MIDI。
3. 查看识谱结果、逐声部节拍提示，试听纯伴奏与旋律提示。图片格式错误或结构明显异常会返回原因。

其他电脑需 Python 3.10+、Pillow 和 Audiveris；Pillow 安装清单为 backend/recognition-requirements.txt。Audiveris 默认读取 macOS 安装路径，其他路径可通过 AUDIVERIS_BIN 配置。本机测试仅支持 localhost:4175/127.0.0.1:4175，不能将绑定改为公网地址直接上线。

## 真实处理链路

上传原图 → 按 EXIF 正向化、灰度和尺度预处理 → Audiveris 批处理 → 原生 MusicXML → 检查完整三谱表与人声/钢琴声部 → 逐小节逐声部时值检查 → 音符 JSON → 声伴钢琴播放器。

不再依赖 MuseScore 自动导出，避免该版本在导出后退出时崩溃。原始 MusicXML 原样用于谱面显示；播放器合并显式识别出的同音延音线，不猜测或补画遗漏连线。

## 节拍检查与边界

- 检查每个声部是否非法重叠、超出小节，再按每个谱表合并时间覆盖。多个声部可以只在小节中途出现，不强制每个声部填满一小节。和弦音同时起奏只占一次时间，休止符和显式空白计入时值。
- 检查音符超出小节、同一声部非法重叠、缺少谱表、声部小节数不一致以及延音线连接异常。
- 试验策略：整张谱最多允许一处不超过半拍的时值空缺，保留为空白，并明确显示位置、声部和缺少拍数。不会补造音符。其他缺拍/超拍终止处理；阈值仅为试验策略，未经准确率校准。
- 《光》：12 小节，检查 36 组声部时值；第 7 小节旋律少半拍。176 个播放音符（旋律 74，钢琴 102），默认 120 BPM。
- 拍数凑满仍可能存在错音、错拍、被错误识别成休止符的音符，或者错误的拍号、连线遗漏。检查不能代替识谱准确性验证。
- 当前仅支持完整常规小节；弱起、复杂多声部、三连音、反复跳房子、中途换拍/变速等可能被拒绝。不得将被拒绝都解释为“图片分辨率低”。

## 代码边界

- backend/omr/pipeline.py：图片预处理、调用 Audiveris、任务结果文件。
- backend/omr/musicxml.py：三行声部识别、时值/延音线检查、转换播放器事件。
- backend/local_recognition.py：仅绑定回环地址的测试服务，单任务执行，限制上传大小、来源和静态文件访问。
- labs/recognition.*：上传、进度、失败恢复、节拍提示、两种播放模式、完整谱面。

上传原图及调试输出保存在 work/recognition-jobs/，不进入静态发布包，也不对静态访问开放。新注册任务状态持久化，24 小时后清理其临时文件。页面不上传外部识谱服务。不将本机测试服务作为公网服务：还缺公网资源配额、访问控制、持久化工作队列和部署验证。

## 已完成验证

- 原有 24 项节拍、和弦、休止符、延音线、结构及任务恢复回归测试仍保留。新增公网测试后，完整测试集共 32 项，需先安装 `backend/public_requirements.txt` 和 httpx，然后运行 `python -m unittest discover -s backend/tests -v`。

- 验证私有源文件/任务目录不可通过静态路由读取，外部来源上传被拒绝。

## 页面认知与后续

本页是现有声伴的本机工具入口；用户首个决策是选择符合范围的谱图。优先级为上传限制、处理状态、可试听结果及明确错误位置。保持现有米色/深绿风格、复用播放器与谱面模块；小屏用整页纵向阅读，不用固定高度裁剪结果。没有改造为新的产品主页。
