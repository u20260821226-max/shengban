# 声伴是怎样实现的

## 1. 整体目标

声伴把五线谱中的音符转成可播放的钢琴声音，让用户选择是否加入旋律提示，并调整速度和调性。现在有两条路径：预置曲目和上传识谱。

## 2. 预置曲目路径

原谱图片 → Audiveris 识谱 → MuseScore 人工校正 → 导出 MusicXML 和 MIDI → 整理为网页可读取的曲目数据 → 放入曲库 → 用户直接试听。

《爱永在》《小幸运》《有一种悲伤》走的是这条路径。人工校正是在制作示范曲库时进行的，不是每次播放时再校正。预置曲目还备有原调、原速的 MP3。

## 3. 用户上传识谱路径

上传图片或 PDF → 检查文件与页数 → 预处理图片 → Audiveris 识谱 → 读取 MusicXML → 检查谱表和节拍 → 返回音符数据及乐谱 → 浏览器钢琴播放。

### 第一步：用户选择谱型和文件

用户先选两行钢琴谱，或三行声乐加钢琴谱。同一首歌可以上传1至6张图片，或一份最多6页的 PDF，并确认页序。

### 第二步：阿里云服务器接收任务

网页把文件发到服务器。服务器是运行识谱程序的远程电脑，因此使用者不必自己安装 Java 和 Audiveris。服务器检查文件格式、大小、页数、使用额度和是否已有任务正在处理。

### 第三步：程序整理图片

PDF 会先转成图片。预处理代码会调整灰度、尺寸等，在满足条件时裁去明显的截图暗边，尽量给识谱程序稳定的输入。这些动作由程序执行，正常使用不依赖聊天 AI 逐张处理。

### 第四步：Audiveris 读取五线谱

Audiveris 在服务器上运行，辨认谱线、音符、休止符、调号和小节等，导出 MusicXML。MusicXML 是数字乐谱，记录音符和乐谱结构，本身不是录音。多页按页序作为同一首歌处理。

### 第五步：声伴检查并转换数据

声伴解析 MusicXML，得到每个音的音高、开始时间、持续时间和所属声部，并检查谱型、小节内时值、超拍、缺拍和部分跨页连接等。

三行谱需要确认“一个旋律声部＋钢琴双谱表”的结构；两行谱需要确认钢琴左右手结构。对于可恢复的结构或节拍疑点，程序最多调整输入重试一次；仍不合格就说明原因，不把部分结果冒充完整生成。检查通过也不能排除所有错音、漏音或连线错误。

最终得到 MusicXML 乐谱和 JSON 音符数据。网页自动播放这条路径不要求用户再制作 MIDI 或 MP3。

### 第六步：浏览器发出钢琴声音

服务器把检查后的数据返回网页。网页用乐谱显示库显示五线谱，并按音符数据安排钢琴采样的播放时间。等待动画读取服务器任务的真实阶段、页数、消息和耗时；波形只是状态装饰，不代表完成百分比。

## 4. 两种播放模式

- 三行声乐谱：纯伴奏只播放下方钢琴左右手；旋律提示将上方主旋律也用钢琴音色播放。
- 两行钢琴谱：完整播放左右手，不把右手自动当成人声旋律删除。

这属于按已经识别出的声部选择播放，不是从一段现成录音中消除人声，也不生成歌词演唱。

## 5. 移调和变速

移调：为音符音高统一加减半音，并同步更新显示的乐谱。用户不用另外制作每个调的音频。当前预置曲目播放器支持上下六个半音。

变速：调整音符的播放时刻和持续时间，保持音高；BPM 数值和滑杆同步变化。备用 MP3 保持原调原速，主播放器负责这些交互。

## 6. 网站、服务器和仓库的关系

GitHub 保存源代码及修改记录。Cloudflare Pages 用于早期预置曲目静态演示。当前统一入口由阿里云服务器提供：既发送网页文件，也通过 API 执行识谱。当前部署是手动更新，GitHub、Cloudflare 和阿里云不会因其中一个改变而自动全部同步。

## 7. 本次页面优化的作用

开场、风景背景、曲目封面、卡片排版和按钮反馈属于前端界面设计与交互优化。它们改善观感、可读性和操作体验，没有改变识谱算法的准确率。当前真实能力仍限定为受支持的简洁印刷五线谱，复杂曲谱可能被拒绝或出现少量误识别。
